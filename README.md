# 文件共享中心 · 手机版

> 一台设备启动服务当「主机」，其他手机用浏览器或「添加到主屏幕」的 PWA 加入，**共享同一个文件夹 + 同一个实时群聊**。
> 由 `H:\Code\file-share-chat`（Flask 桌面版）改造而来，原项目保持不变。

---

## 一、为什么是这个架构

| 约束 | 说明 | 设计结论 |
|---|---|---|
| 浏览器无法监听端口 | H5/PWA 没有 `listen/ServerSocket` 能力，纯网页**不可能**当服务器 | 「手机启动」必须由一个本地进程承担（PC 上的 Python / 安卓 Termux 里的 Python / 云服务器） |
| WebRTC 仍要信令 | 交换 SDP/ICE 需要固定地址的信令端，且主机页面须常驻前台 | 局域网直连 `http://主机IP:端口` 更简单可靠 |
| iPhone 后台限制 | iOS 不允许 App 长期监听端口 | iPhone 只能当**客户端**，主机交给 PC / 安卓 / 云 |

所以本项目做成**双角色、主机地址可配置**：前端所有请求都走一个 `API_BASE` 变量，任何手机都能在「连接」页切换要加入的主机，也能在自己跑服务时切回本机。

```
┌──────────────── 主机（任选一台，持有 download/ 共享目录）────────────────┐
│  Windows：start.bat        Linux/Mac：start.sh        安卓：termux-start.sh │
│  python server.py --port 5000   →  0.0.0.0 监听，提供 HTTP API + WS 群聊  │
└──────────────────────────────┬──────────────────────────────────────────┘
                               │ 同一 WiFi / 手机热点
        ┌──────────────────────┼──────────────────────┐
        ▼                      ▼                      ▼
   安卓手机浏览器          iPhone Safari           另一台电脑
   或 PWA（主屏幕）         或 PWA（主屏幕）          浏览器
        └────────── 都指向同一个 http://主机IP:5000 ──────────┘
```

## 二、快速开始

### 场景 A：PC 端当主机（最省事）

1. 双击 `start.bat`（首次会自动建 `.venv` 并装依赖）。
2. 窗口里会打印：

   ```
   本机访问     http://127.0.0.1:5000
   局域网访问   http://192.168.1.8:5000
   共享目录     ...\download
   扫码加入     已生成 ...\访问二维码.png
   ```

3. **所有手机连同一个 WiFi**，浏览器打开「局域网访问」地址即可。
4. PC 端也可以用命令行自定义端口和共享目录：`python server.py --port 5000 --dir D:\共享文件夹`

> 首次启动若 Windows 弹出防火墙提示，勾选「专用网络」允许访问，否则手机连不上。

### 场景 B：安卓手机当主机（不需要电脑）

1. 安装 **Termux**（建议 F-Droid 或 GitHub 官方包，应用商店旧版常有问题）。
2. 把整个 `file-share-chat-phone` 目录拷到手机，在 Termux 里执行：

   ```bash
   termux-setup-storage          # 第一次，授权访问文件
   cd ~/storage/shared/file-share-chat-phone   # 按实际路径调整
   bash termux-start.sh
   ```

3. 脚本会自动装 Python 与依赖、执行 `termux-wake-lock` 防止休眠，然后打印局域网地址。
4. **保持 Termux 在前台**（或在通知里点 `Acquire wakelock`）。安卓杀后台后服务会停，这是系统限制。
5. 其他手机扫 `访问二维码.png` 或输入地址加入。

> 网页里的邀请二维码由前端生成，不依赖任何 Python 库；只有启动时额外生成的 `访问二维码.png` 需要 `qrcode` + `Pillow`，装不上也不影响共享与群聊。

### 场景 C：iPhone 加入

Safari 打开主机地址 → 底部分享按钮 → **添加到主屏幕**，之后可全屏启动，体验和 App 一致。iPhone 不能当主机，但可以上传、下载、群聊、切换主机，功能与安卓完全一样。

### 扫码加入（推荐给多人）

每个主机在「连接」页都会用前端直接生成一张邀请二维码（不依赖服务端，安卓 / iOS App 内同样可用），内容形如：

```
http://192.168.1.8:5000/?host=http%3A%2F%2F192.168.1.8%3A5000
```

前端读到 `host` 参数会**自动把该地址设为目标主机**并记住，不需要对方手动填 IP。主机启动时额外生成的 `访问二维码.png` 可留在电脑上供别人扫，二者等价。二维码编解码库放在 `static/` 下，**完全离线可用**。

## 三、功能对照

| 功能 | 手机端表现 |
|---|---|
| 上传 | 多选文件 / 整个文件夹 / 直接拍照上传，带百分比进度条，重名自动加 `(1)` |
| 文件列表 | 卡片流、按类型彩色图标、搜索、下拉刷新、文件夹优先排序、总容量统计 |
| 在线预览 | 图片、视频、音频、PDF、TXT 直接在弹层里看（新增 `/preview`） |
| 下载 | 单文件下载、文件夹自动打 ZIP、多选批量打包、iOS 会新标签打开可长按保存 |
| 管理 | 「管理」进入多选，全选 / 批量打包 / 批量删除，删除前二次确认 |
| 实时群聊 | WebSocket 气泡消息、昵称、在线人数、加入/离开系统消息、断线指数退避重连 |
| 多端同步 | 任一设备上传或删除，其他所有手机**立即自动刷新**列表（`files_changed` 广播） |
| 分享通知 | 上传成功后自动在群里发一条「分享了 xxx」 |
| 聊天历史 | 新加入者能看到最近 100 条消息（服务端内存，重启清空） |
| 主机切换 | 扫码 / 剪贴板 / 附近主机搜索 / 手动输入四种方式，保留最近 5 台主机，一键恢复本机 |
| PWA | 可安装到主屏幕、全屏启动、离线能打开界面壳（API 不缓存，避免连错主机） |
| 状态 | 顶部连接灯、心跳探测、在线设备数、共享项目数、主机 IP |

### 加入其他主机的几种方式

| 方式 | 怎么用 | 适用场景 |
|---|---|---|
| **扫码连接** | 「连接」页 → 扫码连接 → 拍照 / 从相册选主机二维码 | 面对面最省事；局域网 HTTP 下浏览器禁用摄像头，自动降级为拍照识别；HTTPS 或本机可用实时摄像头 |
| **剪贴板自动识别** | 复制别人发的链接 → 点「剪贴板」，或直接在输入框粘贴 / 在页面任意处粘贴 | 微信、短信里收到的地址，粘贴即连；从别处切回页面还会自动提示 |
| **附近主机搜索** | 点「附近主机」，自动扫同网段 `1~254`，端口默认 `5000/5001/8000/8080`（框里可增删，当前端口自动加入） | 忘了对方 IP 或端口不一致时；兼容老 PC 桌面版（`/health` 不通时回退探 `/files`），显示文件数与在线人数 |
| **手动输入** | 输入框填 `http://IP:端口`，也支持只填 `IP` 或 `IP:端口` | 最稳的兜底 |
| **扫码自动配置** | 扫主机「连接」页生成的二维码，链接带 `?host=` | 对方打开即自动连上，无需任何输入 |
| **系统分享 / 复制链接** | 「分享本机」或「复制链接」把地址发给朋友 | 反向邀请别人加入自己 |

> 顶部连接灯可点击，直接跳到「连接」页。深链 `?tab=files` / `?tab=chat` / `?tab=connect` 可打开指定页面。
>
> **状态栏适配**：网页端用 `--safe-top`（`env(safe-area-inset-top)` + 原生可注入的 `--extra-top`）统一撑开顶部；安卓 App 去掉了重复的原生栏，并让 WebView 避开系统状态栏与导航栏，不会再和信号栏重合。
>
> **多端适配**：同一套页面按宽度分五档布局——手机（<600）、大屏手机/小平板（≥600）、iPad 竖屏（≥768，文件两列 + 上传区横向）、iPad 横屏/小 PC（≥1024，连接页两列）、标准 PC（≥1280，多列卡片）与超宽屏（≥1600，限宽居中）。手机横屏矮屏自动压缩工具栏；hover 动效只在有鼠标的设备启用，触屏点击不留残影。

## 五、API（与原项目基本兼容，方便老前端迁移）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` | 手机 H5 首页 |
| GET | `/health` | 心跳：在线数、共享项目数、局域网 IP |
| GET | `/files` | 文件/文件夹列表 JSON |
| POST | `/upload` | 多文件上传（`file` 字段） |
| POST | `/upload-folder` | 文件夹上传（`files[]` + `folder_name`） |
| GET | `/download/<name>` | 下载文件 / 文件夹自动打包 ZIP |
| GET | `/preview/<name>` | 在线预览（不强制下载） |
| GET | `/download-selected?name=a&name=b` | 多选打包 |
| GET | `/download-all` | 全部打包 |
| POST | `/delete-selected` | 批量删除（JSON `{"names":[...]}`） |
| DELETE | `/delete/<name>` | 单个删除 |
| POST | `/clear-download` | 清空共享目录 |
| WS | `/chat?nick=昵称` | 实时群聊 |
| GET | `/qr.png` | 加入本主机的二维码 |

服务端参数：`--host`（默认 `0.0.0.0`）、`--port`（默认 5000）、`--dir`（共享目录）、`--no-qr`。

## 六、常见问题

| 现象 | 排查 |
|---|---|
| 手机打不开 | ① 手机与主机是否同一 WiFi；② 主机防火墙是否放行 5000 端口；③ 路由器开了「AP 隔离 / 访客网络」会禁止设备互访，关掉它；④ 用手机开热点让所有设备连它最稳 |
| 连上但文件列表空 / 顶部显示「主机不可达」 | 去「连接」页看当前主机地址，点「恢复为当前页面所在设备」，或重新扫主机二维码 |
| 端口被占用 | PC 端改用其他端口再启动，例如 `python server.py --port 5001`，二维码和链接会自动用新端口 |
| 扫描不到非 5000 端口的主机 | 搜索结果里展开「端口」框，把对方端口加进去（如 `5000,5001,9000`），点「重新搜索」；当前主机端口已自动包含。旧 PC 桌面版没有 `/health`，已用 `/files` 兜底识别 |
| 网页二维码空白 | 刷新页面即可（前端生成，不依赖 Python 库）；若是启动时的 `访问二维码.png` 没生成，才需要 `pip install -r requirements.txt` |
| Termux 切后台后别人连不上 | 安卓杀后台，重新打开 Termux 再跑脚本；通知栏锁定 wakelock |
| iPhone 下载没反应 | iOS Safari 对 `download` 属性支持有限，会新标签打开；长按图片/链接选「存储到文件」 |
| 大文件上传中断 | 保持页面在前台、屏幕常亮；服务端不限制大小，但手机浏览器后台会挂起上传 |

## 七、以后要跨外网（异地互传）

前端**不用改**，只要让主机有一个公网可达的地址，然后在「连接」页填它：

- **内网穿透**：frp / Cloudflare Tunnel / cpolar，把本机 5000 映射出去；
- **云服务器**：把本项目丢到云主机，所有手机都填 `https://域名`；
- 走 HTTPS 时 WebSocket 会自动用 `wss://`。

> ⚠️ 当前版本**没有登录鉴权**，只适合可信局域网。若暴露公网，务必在前面加反向代理 + 口令（Nginx `auth_basic` 或简单 Token），否则任何人都能删你的文件。

## 九、手机原生 App：手机自己当服务端

网页版/PWA 受浏览器沙箱限制无法监听端口，所以「手机当主机」必须靠原生 App 内嵌服务。本项目提供两个平台：

| 平台 | 交付物 | 能否直接安装 | 当服务端 |
|---|---|---|---|
| Android | `android/文件共享中心.apk`（已签名，约 70KB） | ✅ 直接安装 | ✅ 前台服务常驻，锁屏也能被访问 |
| iOS | `ios/` 完整 Xcode 工程源码 | ❌ 需 Mac + Xcode 签名导出 IPA | ⚠️ 仅 App 在前台时可用（系统限制） |

**两端都内嵌了同一套 HTTP + WebSocket 服务**（与 `server.py` API 一致），因此每台手机既能当主机、也能在「连接」页填地址变成客户端；三端（网页版 / 安卓 App / iOS App）可以任意互为主机和客户端，共享同一个文件夹与群聊。

### Android

安装 `android/文件共享中心.apk` → 允许通知权限 → 打开即启动服务，顶部显示 `http://手机IP:5000`，点「复制地址」发给朋友即可加入。详细说明见 [android/README.md](android/README.md)，重新构建见 `android/build-apk.bat`。

### iOS（为什么不能直接给 IPA）

Apple 的编译、签名、IPA 导出只能在 **macOS + Xcode** 上完成，且需要 Apple ID 签名（免费账号签名有效期 7 天，付费开发者账号 1 年），Windows 上无法生成可安装的 IPA。因此交付的是**完整可编译的 Xcode 工程**，在 Mac 上打开、选自己的 Team、Archive 即可导出 IPA，步骤见 `ios/README.md`。

另外 **iOS 会在 App 进入后台后很快挂起网络 socket**，所以 iPhone 只能在前台运行期间当主机；切后台、锁屏后服务会中断，这是系统限制，任何第三方 App 都无法长期绕过。iPhone 当客户端（连 PC / 安卓主机）则完全正常。

> 没有 Mac 也不想在 iOS 上折腾签名：iPhone 直接用 Safari 打开主机地址 → 「添加到主屏幕」，即可获得全屏 PWA 当客户端，功能与 App 一致。

### PC 端还有一个 Rust 版

`pc-rust/` 是同一套服务的 **Rust 实现**：编译后是**单个 exe**，移动端前端（含离线二维码库）已编译进二进制，运行时不需要 Python 或任何运行库。

**双击 `file-share-pc.exe` 打开的是图形启动器窗口，不是黑色命令行窗**。窗口里显示服务状态、本机/局域网地址、共享项目数与在线设备数，还可一键复制邀请链接、打开网页、打开共享文件夹；关闭窗口即停止服务。

```bash
cd pc-rust
build.bat                                   # Windows 双击；或 bash build.sh
file-share-pc.exe                           # 图形启动器（默认 5000 端口，共享目录 ./download）
file-share-pc.exe --port 5001 --dir D:\共享文件夹
file-share-pc.exe --no-gui                  # 纯后台模式，不显示窗口（适合计划任务）
```

API 与 Python 版完全一致，**三端可以混着用**（Rust 版当主机、Python 版当主机、手机 App 当主机都行）。详见 `pc-rust/README.md`。
